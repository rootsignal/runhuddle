# RunHuddle 0.10.0 preview

More useful attention requests, quieter alerts, and better navigation to existing terminals.

- Needs input details show the request type, observed waiting time, and bounded request excerpts when available. Waiting sessions are ordered oldest first. Missing prompt details are explicit; all answers still happen in the terminal.
- Settings → Notifications includes independent input/completion alerts, sound, quiet hours, one-hour snooze, and optional one-time waiting reminders. Session actions can mute a project’s alerts.
- Bursts are combined into one notification. Resolved requests are dropped before delivery; grouped alerts open Now.
- iTerm2 discovery includes split panes and verified TTY matching. Manual terminal choices are remembered only while their identifying details remain unchanged in the current app run. Closed-history duplicates no longer block an otherwise unique live title match.
- Attached tmux panes on the default local server can be selected through Terminal.app or iTerm2. No session creation or keystroke injection.

Validation: 46 Swift and 77 Python tests, light/dark offscreen component review, and isolated tmux inventory/pane selection. The release pipeline additionally checks standalone packaging and signed updates. iTerm2/Ghostty and end-to-end tmux UI validation remain pending on those setups. Codex currently supplies the request category, not the full prompt text, through this status adapter.

Project context is next; no MCP integration was added.
